# Telegram WS для Android

Локальный MTProto-прокси для Telegram. Приложение работает в фоне на том же устройстве и передаёт трафик в датацентры Telegram через защищённый WebSocket. Для прямого маршрута отдельный сервер не нужен.

**[Скачать APK](https://github.com/Gurenomaru/tg-ws-proxy-android/releases/latest)** · [Как собрать](#сборка) · [Приватность](#приватность)

## Подключение

1. Установите APK из **Releases**. Поддерживается Android 8.0 и новее.
2. Запустите приложение и нажмите **Запустить прокси**.
3. Выберите **Открыть в Telegram** и подтвердите подключение прокси в Telegram.
4. Если сообщения или файлы загружаются плохо, нажмите **Проверить связь с Telegram**. Проверка отдельно показывает обычный DC2, медиа DC2 и DC4 и CDN DC203. **Журнал соединений** показывает тип выбранного маршрута и ошибки подключения.

Прокси слушает только `127.0.0.1:1443`. Его можно остановить в приложении или из уведомления. Если Telegram остался настроен на локальный прокси, после остановки сервиса отключите прокси в самом Telegram или запустите сервис снова.

## Фоновая работа

После запуска прокси приложение предложит отключить оптимизацию батареи для Telegram WS. Запрос можно открыть повторно кнопкой **Настроить работу в фоне**. Если Android или производитель явно ограничил фоновую работу, эта же кнопка ведёт в настройки приложения. На Android 13 и новее разрешите уведомления, чтобы видеть статус и кнопку остановки в шторке.

Если Android выгрузит процесс работающего прокси, система может запустить сервис снова. После выключения кнопкой **Остановить прокси** запустите его вручную, когда он снова понадобится.

## Обновления и установка

При открытии приложения Telegram WS проверяет последний стабильный релиз на GitHub не чаще раза в сутки. Запрос можно повторить кнопкой **Проверить обновления**. Если вышла новая версия, нажмите **Скачать и установить**. Telegram WS скачает APK из официального релиза, сверит SHA-256, имя пакета и подпись и откроет установщик Android. При первом обновлении Android может попросить разрешить установку из Telegram WS. Установку нужно подтвердить в системном окне. Страницу релиза можно открыть из того же окна приложения.

Для установки используйте APK из официального раздела Releases и сверяйте SHA-256 по файлу контрольной суммы, если он приложен к релизу. Android при обновлении проверяет подпись пакета. Браузер и Play Защита могут дополнительно предложить проверить APK, полученный вне Google Play. [Google Play Защита](https://support.google.com/googleplay/answer/2812853/)

## Автоматический выбор

Автовыбор с резервом через публичные серверы Flowseal включён по умолчанию, пока пользователь не изменил эту настройку. На Wi-Fi прокси сначала пробует прямые или настроенные маршруты, затем резервные. При подключении Telegram прокси проверяет кандидатов в каждой группе параллельно и ранжирует их по времени до проверенного ответа MTProto. Если прямые и настроенные маршруты не отвечают вовремя, автовыбор на Wi-Fi сравнивает резерв Flowseal по WS и WSS в одной группе. Успешный результат для каждого дата-центра и типа трафика используется при следующих подключениях в течение пяти минут. На мобильной сети при разрешённом автовыборе прокси сначала проверяет те же серверы Flowseal на порту 80, что и ручной мобильный режим. Если среди проверенных маршрутов нет доступных, прокси пробует резервные. При смене сети замеры выполняются заново при следующем подключении. В простое отдельные проверки не запускаются.

Автовыбор можно отключить в **Настройках маршрутов**. Сохранённое отключение действует и после обновления. Он при необходимости использует WebSocket на порту 80. На этом маршруте сохраняется шифрование MTProto, внешнее TLS-соединение отсутствует.

## Расширенная диагностика

Если прокси не работает в конкретной сети, откройте **Расширенная диагностика** и выберите **Полная проверка**. Её можно запустить с выключенным прокси. Тест сравнит IPv4 и IPv6, проверит DNS, TCP, TLS, WebSocket и ответ MTProto. В него входят официальные адреса Telegram, контрольный HTTPS, настроенные маршруты Cloudflare и публичный список Flowseal.

После завершения отправьте файл .txt через меню Android. Для сравнения запустите диагностику отдельно на Wi-Fi и на мобильной сети. Отчёт содержит версию приложения и Android, тип сети, параметры маршрутов в виде признаков и результаты тестов. Отчёт отдельно показывает обычные подключения и служебные пробы, включая число ответов, зависших соединений и сетевых переподключений. В отчёте также видны разрешения для фоновой работы и категория предыдущей остановки процесса по данным Android. IP телефона, SSID, секреты, учётные данные и переписка в него не входят. Публичные серверы при проверке видят IP входящего соединения.

## Маршруты

| Маршрут | Как используется |
| --- | --- |
| WSS Telegram | Основное подключение. Для DC2, DC4 и CDN DC203 предусмотрен IPv4 по умолчанию и несколько TLS-имён. |
| Собственный SOCKS5 | Настраивается вручную. При необходимости его можно поставить первым в очереди. |
| Cloudflare Worker или свой домен | Настраивается вручную для сетей, где прямой WSS недоступен. [Worker](https://github.com/Flowseal/tg-ws-proxy/blob/main/docs/RU/CfWorker.md) · [Домен Cloudflare](https://github.com/Flowseal/tg-ws-proxy/blob/main/docs/RU/CfProxy.md) |
| Публичные домены Flowseal | WSS на порту 443. Автовыбор может использовать этот маршрут как резерв. |
| Мобильный режим Flowseal | По выбору пользователя сначала проверяет публичные домены по WS на порту 80. Шифрование MTProto сохраняется, TLS на этом маршруте отсутствует. |
| Прямой TCP | Резервный маршрут. Его можно отключить в настройках. |

Если выбранный маршрут завис, приложение пробует альтернативы. После смены Wi‑Fi или мобильной сети прокси закрывает старые соединения, чтобы Telegram мог открыть новые. Доступность маршрутов зависит от сети и датацентра. Встроенная проверка измеряет ответ на служебный запрос MTProto. Скорость загрузки конкретного файла зависит от маршрута к этому файлу. [Как Telegram загружает файлы через CDN](https://core.telegram.org/cdn)

## Приватность

- В приложении нет аналитики, счётчиков, рекламных SDK или автоматической отправки журнала. Прокси не запрашивает контакты, номер телефона, доступ к файлам или аккаунту Telegram.
- Секрет локального прокси создаётся на вашем устройстве. Кнопка **Открыть в Telegram** передаёт ссылку одному из двух пакетов официального клиента. Копирование по вашей команде помещает ссылку с секретом в системный буфер обмена на Android 10 и новее.
- Настройки хранятся в закрытом хранилище приложения и исключены из резервного копирования. Сохранённые учётные данные SOCKS5 шифруются ключом Android Keystore. Журнал хранится в памяти приложения. В него не записываются содержимое трафика, секреты и имена частных серверов.
- При включении стороннего маршрута его оператор может видеть ваш IP, время и объём соединений. Логин и пароль SOCKS5 при авторизации передаются вашему серверу без собственного шифрования SOCKS5. Используйте доверенный сервер и защищённую сеть. [Аутентификация SOCKS5](https://www.rfc-editor.org/rfc/rfc1929)

## Экспериментальный движок Rust

Пререлиз 0.3.1 использует интерфейс, настройки маршрутов и Android-сервис из стабильной 0.2.11. По умолчанию прокси работает на Java. Чтобы попробовать Rust, остановите прокси, включите **Экспериментальный движок Rust** в настройках маршрутов и снова запустите прокси. Выбор можно изменить тем же способом. Активный движок виден в журнале при ошибке запуска и в отчёте TXT.

Rust использует асинхронный сетевой цикл, те же группы маршрутов и отдельные проверки ответа MTProto. Для TLS в Rust используются встроенные корневые сертификаты WebPKI. На обоих движках при смене сети прокси пересоздаёт соединения. В Rust обнаружение зависания после первого ответа основано на повторной отправке данных без ответа.

## Сборка

Нужны JDK 17, Android SDK Platform 35, NDK 27.2.12479018, Python 3 и стабильный Rust с Android-целями. Установите цели командой ниже и запустите Gradle из корня репозитория. Gradle собирает один APK для ARM и x86, включая 32-битные устройства с Android 8.0 и новее.

```text
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
```

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Путь к отладочному APK — `app/build/outputs/apk/debug/app-debug.apk`. Команда `:app:assembleRelease` собирает APK без подписи. Для публикации подпишите его своим ключом. Публичный релиз использует отдельную подпись. Если на телефоне уже стоит debug-сборка, сначала удалите её. При удалении Android сотрёт настройки локального прокси.
